## The problem

There are at least sixteen apps for quitting nicotine pouches, and they all do the same thing: a countdown, a streak, a cheerful push notification, and a paywall. They treat quitting like a motivational problem.

The evidence says something less flattering. A Cochrane review found no effect of smartphone apps on quitting. What does move the number is commitment: money put down at the moment you commit roughly doubles abstinence. And for pouches specifically, nobody has prospective data on what withdrawal actually does to your sleep, heart rate, or HRV, because the category is too new.

Abrupt is built on both of those facts. It's positioned as MacroFactor for quitting nicotine: a tracker and a commitment device for people who respond to data, not encouragement. It never claims to be a treatment. Every number it shows links to the study it came from.

## The build

### Start with the evidence

Before writing code I reviewed about 130 sources on quitting pouches and turned the useful ones into a typed evidence library: 70 sources, 106 claims, and 16 predictions, all in JSON with a linter and a build plugin that turns every claim into a typed identifier. If a screen cites a claim that doesn't exist, the build fails.

The predictions drive the charts. A published prediction renders as a shaded band, never a line, because a line would claim a precision no source gives. There are no outcome colors either: no green for good, no red for bad. Amber means "your data." Teal means "go somewhere." That's the whole palette.

### Charge at the commitment moment

Setting a quit date is the commitment. So that's where the paywall is: fifteen dollars, once, no subscription, no refunds, and the app tells you not to buy it until you've picked a date. The copy is tested in CI. A script fails the build if anyone writes "easy," "journey," or "you've got this."

### Health data without becoming a health-data company

HealthKit is read-only. Abrupt reads daily rollups with background delivery and never copies raw samples into its own store. SwiftData is local only, in an App Group container, with no iCloud sync. The watch app and widgets never write to the store; they send events and read snapshots, because two processes writing one SwiftData store is where lost writes live.

Research mode, for the gap in the literature, works without a server. There's a published upload format and an open-source receiver that a research partner runs themselves. Payloads are encrypted to the study's key with HPKE and reuse the export serializer, so research mode can never send something the user couldn't export for free. The whole mode is behind a build-time flag: on in TestFlight, off in the App Store build. Feature flags are compiled in rather than fetched, so the shipped app never phones a third party on launch.

### Built to be built by agents

Most of the Swift lives in nine local packages that compile on Linux, with Swift Testing and a GitHub Actions gate. That's deliberate: a lot of the code is written by Claude Code sessions, some in cloud containers with no Xcode. The git history is honest about it. Of 126 commits in the first week, 86 are authored by Claude and 40 by me. My job was the research, the decisions, the design system, and the review.

### The relapse model

A lapse is one pouch. It resets the day count but doesn't end the attempt. A relapse is seven consecutive days with a pouch. The vocabulary is fixed in a glossary and the rules live in the core package with tests, because an app about quitting that gets "did I fail" wrong is worse than no app.

## How it went

Planning finished on Oct 7, 2026, with thirteen accepted architecture decisions by Oct 13, and version 1.0 shipped to the App Store the same month: iPhone and Apple Watch, with widgets, a craving Live Activity, and the full evidence library on board. Fifteen dollars, once.

What's next:

- User interviews with pouch quitters, and an n-of-1 HRV pilot on my own quit with an Apple Watch and a ring, to start filling the research gap.
- An optional taper in 1.1.
- A cotinine-verified deposit contract in 2.0.
- Vapes as the second product. Android only if the iOS product proves the model.

## What it demonstrates

Starting a product from an evidence review instead of a feature list. Designing privacy as architecture rather than a policy page. Making the money model match the behavioral science. And running an agent-written codebase with enough structure, typed evidence, Linux-buildable packages, and a tone check in CI, that the output stays trustworthy.
